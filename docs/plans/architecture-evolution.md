# AgentRoom 架构演进实施方案

这是 GET-519 的设计交付，**尚未启动以下代码重构**。基线为 `v0.2.0-alpha.1`，不承诺日期。后续从 `getyak/agentroom:main` 开始，每期独立关联 Linear、PR、测试与验收。

## 共同约束

保留联系人/会话/运行 ID、资料目录、bundle ID 与包名。默认仍是一份工作区、一个自有 utility 和有界队列，不增加第二个模型池。普通聊天、工具审批、创作授权各自保持接受语义。数据变更先定义恢复；未知写入不能靠自动重试消除。

审批领域的具体后续提案见 [GET-530：Raft 研究与审批架构](../superpowers/specs/2026-11-13-approval-architecture-design.md)。它补充以下入口/调度收拢的设计依据，未启动运行时代码迁移。

## 阶段一：收拢工作区入口

**问题。** index.mjs 同时组装模块、处理传输和编排操作，容易遗漏事务、通知或恢复分支。

**交付。** 保留 `createPersonalServer(options)` 的外部接口，内部建立工作区应用模块。HTTP 路由只校验、调用、响应，领域写入留在应用模块及存储事务里。可研究 `dispatch / subscribe / prepareClose / close` 小接口，以实际调用方需要决定，不为假想部署叠加转发层。

范围为 `server/index.mjs`、内部应用模块及既有固定 IPC 对照。路径、状态码、clientId 和指纹保持兼容，白名单不扩大为任意 URL；退出仍先冻结写入，再核对状态，最后确认自有进程退出。

**验证与完成标准。** workspace/messenger/native-host 套件固定旧行为；增加同一请求跨传输的幂等测试。故障注入提交前后、响应丢失和并发退出。完整浏览器和隐藏原生入口通过后移除旧分支；本阶段不换数据库格式。

## 阶段二：接受与调度规则

**问题。** 接受快照、并发通道、未知作用和停止保护分散在 Messenger、worker 与适配器中，新入口容易漏规则。

**交付。** 将接受运行、判断是否可启动整理成可单独验证的接口，所有模型仍通过 PersonalWorker。CLI 和 A2A/MCP 保留实际不同的会话、停止和回执能力，不假设统一强取消。

**验证与完成标准。** 覆盖配置随后改变、成员重入、同端点多绑定、排队取消、停止未确认、登录失效和回执丢失。历史上下文必须对本次回复的全部受众可见；移除后重入不能发布旧成员时期的回复或表情。崩溃后核对原 runId/taskId/栅栏。新联系人、调度和设备入口均调用同一规则，未知写入不产生第二次发送；并发和顺序契约保持一致。真实 CLI 逐提供商另记证据。

## 阶段三：联系人提议与申请

**问题。** 本机采用、角色建议和设备目录已经存在，但没有完整申请对象；device_request 只记录执行。

**交付。** 设计独立、版本化的 `contact_request`（拟议名称），绑定目标身份，明确决定的持有方及远端投影。生命周期包括草稿、待处理、接受、拒绝、撤销、过期。阿屋可形成可审阅的提议，产品接口负责实际写入。

本机地址簿采用与跨设备关系分开；后者需要真实对端协议、身份和撤销。先做自有设备可审核流程，跨所有者好友授权另立设计及威胁分析，不用共享令牌代替账号归属证明。

**验证与完成标准。** 覆盖同名、重复点击、旧版本接受、过期/撤销和对端离线；重试返回原回执。接受前不泄露原聊天、凭据或角色全文。两隔离实例通过后做真实双设备验收。界面区分建议、保存、发送、对方接受、可调用，只有相应真实回执才能推进状态。

## 阶段四：作品访问与一致备份

**问题。** 作品由 DB 指针、不可变对象和 Finder 投影共同构成，单独复制 SQLite 不能证明完整恢复。

**交付。** 带版本清单与哈希的一致工作区备份，包含 DB 快照、必要对象和原凭据密钥，记录应用/格式版本。恢复先在隔离目录校验，再切换；冲突、未知运行和未完成物化进入恢复报告。

**验证与完成标准。** 覆盖中断、缺对象/密钥、空间不足、人编辑 current、旧格式、未决外部请求。不自动重放写入或覆盖正常资料。另一隔离目录恢复后的身份、版本、授权和待核查状态一致，有损情况明确报告并保留原资料。本阶段不做在线 SQLite 多端复制。

## 阶段五：正式分发与升级

**问题。** 当前 Apple Silicon ZIP 是 ad-hoc Alpha，尚未公证，也没有已交付的自动更新器。

**交付。** 在正式签名配置可用后建立 Developer ID、公证、staple、公开下载和升级验证，保留 clean commit、架构、SHA-256 及签名回执。之后接入[自动更新设计](../superpowers/specs/2026-11-11-macos-auto-update-design.md)，下载、提示、退出与恢复各自可观察。

**验证与完成标准。** 干净 Mac 首装、从上一公开版本升级、断网/坏包/签名不匹配、空间不足、运行或待审批时重启、原资料与 keychain 连续性。普通与测试资料分别检查；本机开发证书不替代 Developer ID。实际安装/升级和恢复通过才算完成，仅生成新包不算升级验收。

## 阶段六：按测量结果拆界面

**问题。** Messenger 同时处理导航、草稿、进度和弹层，按文件行数拆组件容易复制状态。

**交付。** 依据回归和性能记录，将导航/选择、草稿提交、会话读取及弹层收拢为独立接口。复用 conversation-state、阅读位置和列表逻辑，不在多个组件重复接受状态。

**验证与完成标准。** 连续提问、失去响应后编辑、切换会话、前进后退、中文输入、焦点、窄屏返回。固定合成数据测长列表/长文，再按瓶颈决定虚拟化或分块。行为和 test IDs 兼容，草稿/焦点不丢；性能改进使用相同条件比较。

## 顺序与门禁

建议先做一、二，统一后续入口的规则。三的协议可先评审，编码依赖接受接口。备份恢复早于自动升级，签名准备可以独立进行；界面拆分按实际问题穿插。

各期启动时写清具体问题、兼容规则、数据变更和验收对象。风险代码独立审查，最新适用 CI 通过后合并；真实验收缺失就保留进行中，不将本机合成检查写成账号、设备或分发通过。
