# Roomie 的实时上下文推荐

用户要求 Roomie 通过 harness 和 tools 不时理解群聊与环境，再提出准确、有用的建议。现有实现只观察安装/登录元数据，角色规划失败时退回关键词模板，不能满足这个目标。

采用现有 PersonalWorker 和隔离 Codex/Pi 执行器，增加只读的群目录、共同群聊正文和环境工具。正文沿用成员、加入边界、资料依赖与公开群限制；不扩大到其他私聊或未加入的群。群目录可以发现未加入的群，但必须区分能否读取正文。

新增独立的主动推荐开关，默认关闭；旧配置监测开关的含义不变。开启后每 60 秒检查上下文是否变化，变化且距上次尝试至少 5 分钟才排入同一个执行队列。后台任务不伪造用户消息、不自动切换后端。重启和未确认停止保留既有恢复栅栏。关闭开关会使排队及运行中的观察失效。

模型按需调用工具，允许没有建议、没有新角色或新群。非空主动建议必须引用本轮工具实际读到的群消息或环境采样。发布前再次检查来源、身份及授权；新消息在下一轮采样，不宣称分析时刻之后的状态。来源依赖写入消息，不能通过阿屋对话泄漏给不在原群的成员。建群和添加角色仍由用户采用。

删除关键词模板和自动补齐的“讨论伙伴”。模型失败明确失败；输出无建议就保持安静。固定频率、预算、权限和 JSON 校验是执行约束，推荐内容由模型判断。

取舍：纯提示词修改不能提供新事实；另建后台模型池会绕过并发和恢复规则，因此选择扩展现有工作队列与受限工具。当前首批仍限支持隔离规划的 Codex/Pi；不把其他适配器的普通聊天能力写成后台理解通过。
