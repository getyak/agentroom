# 群聊就是协作空间

用户修正上一轮独立房间的产品形态，要求直接融合到现有系统：Agent 通过 tools 建群、挑选合适的 Agent 联系人、准备外部邀请；外部访客进入相同聊天样式；notes 和小游戏是 artifacts；Agent 始终知道成员及其状态。本次沿用已授权的直接实现方式，构建者自行处理实现取舍。

## 选择

继续叠加独立房间会保留双份消息和执行系统；仅把旧房间嵌进聊天也不满足统一上下文。采用现有 `thread/contact/message/run` 作为唯一协作记录，分享是附属于群的可撤销权限，复用 PersonalWorker、联系人响应策略及 ArtifactStore。旧 `play_room` 内容迁移进普通群，旧邀请能力仍可映射到该群；不自动重放旧模型请求。

Raft 只作为设计参考。固定源码 `botiverse/raft-source@db5e399f017d584e49597e3a28757645d6807893`：`manual/agent-knowledge/channel.md`、`packages/cli/src/ax/channelCard.ts`、`packages/shared/src/agentOps/passiveResources.ts`、`packages/server/src/routes/channels.ts`。吸收分开的操作权限、带版本的群卡和上下文新鲜度，结合本项目实现，不移植其代码。

## 日常体验

普通私聊或群聊中的 Agent 能使用 `group_contacts`、`group_create`、`group_info`、`group_add_agents` 和 `group_invite`。创建的群直接出现在原会话列表，源聊天显示可打开的群卡。只根据明确的协作需求建群，按角色说明选择已有联系人，不虚构新 Agent。内部组织有单次请求预算和委派深度上限，Agent 回复不会无限唤醒其他 Agent。

群标题旁提供分享、成员和群作品入口。移除独立“来玩”导航与案例门户；数字分身、旅行、共同项目作为群聊中的示例目标和 artifact 模板保留。主人和访客复用消息时间线、成员展示、输入区与群作品组件。访客没有联系人全库、设置、审批及私有 Library 导航。

主人可以让 Agent 准备邀请卡。默认对外开放先审核公开背景、公开 Agent 身份和起始可见范围；审核后自动启动原有临时 HTTPS 通道并生成链接。协作规则可显式允许 Agent 为新建空群自动开放邀请，既有私聊或旧群仍需要具体范围审核。规则变更是主人本地能力，访客不能修改规则或批准开放。链接能力不进入模型或普通工具回执，主人在原聊天/群头的邀请卡直接复制。

访客看预览、填昵称并接受，获得群内独立联系人身份。昵称不验证真人身份。加入、离开、移除、最近连接和 Agent 执行状态分别记录，不把在线说成已读、已邀请说成已加入。主人/AI/访客身份在共享时间线中清楚区分。同域名回访恢复原身份；临时通道换域名按现有边界重新接受。

## 上下文与权限

每轮输入和 `group_info` 返回当前群目的、成员类型、加入状态、最近连接观测、Agent 就绪/排队/执行/等待主人/不可用状态、可见范围和权限版本。变更成员或共享规则的工具必须携带读到的版本；陈旧版本返回新的群卡，不执行变更。忙闲是观测，不是语义阅读证明。

公开群中所有模型执行都使用明确发布的 Agent persona、群背景、公开起点后的本群消息和公开 artifacts；不读取旧私聊、长期记忆、原联系人私密 instructions 或旧群附件。Owner 输入也走相同公开范围，防止通过普通消息路由绕过访客隔离。只有兼容的本机 Codex/Pi 能供外部参与者调用。沿用上一版已验证的 Codex 0.163.0 空白 home 与同账号文件认证链接，不回退到普通 CLI 或第三方私人连接器。

访客发言使用同一 Messenger/PersonalWorker 队列，身份来自服务器会话，不能在正文指定 actor。配额默认 24 小时、5 位访客、30 次模型执行（多 Agent 每个执行分别计数），每条消息 4000 字、便笺 12000 字，最多 20 个待执行。相同 clientId 正文不可变。关闭邀请或移除访客使其现有会话失效；移除同时轮换邀请。每次工具、读取和最终发布都重查权限，晚结果不能发给已撤销范围。普通和访客执行共用未知停止门禁。

## Artifacts

共享便笺是真实 document artifact，具有 ID、版本、贡献者、CAS 文本编辑和 Library 入口，不再保存在 room.board.notes。小游戏先提供受控的投票/问答活动 artifact：immutable JSON 题目绑定 revision，参与状态按会话身份持久化并去重；不执行访客任意程序。讨论产生的文档/静态网页继续通过现有共创计划、批准、原生工具、预览和交付流程。

群作品只有明确对该分享范围发布的版本可被访客读取。既有私人作品不能因为拉人而自动公开；未来访客可读群已发布作品是分享审核的一部分。更换/撤销作品范围会阻止旧版本继续访问。访客仅能编辑被允许的固定便笺路径或提交活动选项，不能通过“编辑便笺”任意写文件或冒充主人贡献。

## 验收

真实 HTTP 验证同一 thread/message/run、加入与移除、原链接恢复、旧上下文不可见、私有 API 拒绝、身份伪造、配额、幂等、成员变更期间的晚回复、旧房间迁移及待核查执行。原生工具测试真实 scoped broker 的建群/拉人/邀请回执和陈旧成员版本，guest 源无联系人库/建群授权。Artifacts 测试 CAS、贡献者、跨群/旧版本拒绝与双访客活动同步。

浏览器和真实 `.app` 验证“私聊提出需求→普通群出现→群内开放邀请→访客相同聊天样式→两位 Agent 回复→共享作品”的流程及 390px 布局。实际 CLI/公网与合成传输分列；独立整分支审查后通过适用 CI、合并、安装，保留原工作区与回退包。Linear 连接恢复则关联任务，否则保留可补录文本和具体失败，不伪造关联。
