# 跨机器 Agent 通讯录

2026-11-13。关联 [GET-513](https://linear.app/getyak/issue/GET-513)。跟踪 [统一目录 #3](https://github.com/getyak/agentroom/issues/3)。用户希望各机器的 Agent 都可以登记，Web 和 macOS 都能看到完整的 Agent 目录，继续使用 Tailscale，并在局域网条件允许时自动直连。

## 当前交付与缺口

已有桌面共享和服务器节点支持受认证的联系人目录、来源机器、在线状态及有限的远端执行。工作区分别登记各来源；不是全局注册表。桌面不再转发导入的远端联系人，避免转发环。目录只含名称、简介和可用状态，尚无统一的头像、模型摘要和能力版本。

辅助 Web 默认有独立资料目录，因此它与桌面可能显示不同联系人。本轮先提供 `pnpm open:personal:web`：识别当前安装包、其实际子进程和构建提交，打开该桌面自有 utility 的回环 Web 页面。它不启动第二个后台，不接管固定开发端口，不修改资料或网络绑定。桌面退出后此网页也不可用。原生登录继续由 macOS 应用完成。

本轮跨 Mac 配置验收和 Web 入口修复不表示下述统一目录已经实现。

## 用户目标

- 一个来源可以是 Mac、服务器或未来支持的执行设备。设备主动登记自己允许发布的 Agent。
- 每个客户端看见相同的已授权来源集合；可识别同名但来自不同设备的 Agent。
- 显示名称、头像、简介、来源设备、能力、可公开的模型配置摘要、可用状态和最近更新时间。
- Agent 在来源机器执行。登录、角色全文、私有路径、聊天数据库及服务凭据保留在来源机器。
- 目录共享、允许发消息、允许配置和允许原生登录分别声明，不用在线绿点代表权限或执行成功。

“完整”指已登记且获准发布的目录，不推断未登记设备或隐藏联系人存在与否。是否提供 Web 发消息和任务入口以用户确认的范围为准；共同的目录和身份层不依赖这一选择。

## 方案选择

推荐常在线的 Mac mini 持有一个统一目录服务。其他设备登记来源，各客户端订阅同一个目录；来源的执行和数据所有权保留。离线客户端使用带时间的缓存。此选择是实现建议，尚未启用新服务。

另一方案是各客户端分别登记全部来源，复用当前节点协议。它能快速配置少量设备，但新增来源、撤销和信息字段需要逐客户端维护，适合作为当前过渡。

SQLite 文件同步不能承担设备登记、权限、冲突与执行所有权，不作为目录实现。统一目录也不要求迁移完整工作区。

## 身份与信息

稳定键为 `(sourceId, agentId)`。设备改名、IP 变化或 Agent 改名不改变身份；同一 CLI 在不同设备上是不同的执行身份。导入记录保留原始来源键，不把客户端的本地连接 ID 当作全局身份。

目录条目需要版本、来源身份、显示字段、能力集合、模型摘要、发布状态及独立的观察时间。客户端自定义备注与来源字段分开保存。头像使用限大小的已验证资源；不允许外部 URL 使查看目录产生任意网络访问。模型摘要不包含 token、认证文件或系统环境。

来源明确选择发布联系人；可另外提供“自动发布今后符合条件的本机 Agent”的显式选项。当前逐项选择不因一次全选自动变成持续授权。已导入的远端联系人不能作为新来源重新发布。

## 登记、权限与更新

来源登记先验证设备稳定身份与配对凭据，取得该来源明确授予的目录权限。Tailscale 提供私网传输，不代替应用授权。目录访问凭据与执行凭据分开管理，浏览器不接收来源 CLI 登录或服务 cookie。

目录服务只暴露专用接口，不开放整个 personal API。需要 Web 发消息时，由独立授权的执行接口将稳定 Agent 键解析为来源端点；每次接受固定来源身份、配置版本和幂等任务标识。响应丢失后核查原任务，不自动重发。不得为方便浏览器绕过现有 Host/Origin 或原生 IPC 检查。

沿用当前 15 秒观察、60 秒离线窗口作为初始默认值。在线状态、来源配置可用状态和执行状态分开。来源失联保留最后目录并显示时间；明确撤下的联系人标记撤下，保留原有聊天。配对凭据撤销后，缓存不能继续显示为可调用。

个人服务连接器按实际能力展示：本机可登录不代表支持独立远端会话；未验收的能力保持不可用并说明来源。资料修改必须说明是在修改共享显示资料、客户端备注还是来源执行配置。

## 实施顺序与验收

1. 完成当前双机共享配置，修复浏览器打开旧资料空间的问题。验证实际安装构建、双方目录、原资料 ID 和消息连续性。
2. 增加带稳定来源键、版本和能力的目录投影及协议；先测试同名、重复登记、来源改名、撤回、过期和转发环。
3. 部署 Tailscale 内的统一目录与设备登记/撤销；macOS 和 Web 使用同一个目录客户端。新设备通过配对取得相同目录，来源凭据不下发给普通界面。
4. 根据 Web 操作范围补齐执行或配置授权，并使用既有持久任务与未知结果保护。

最终验收至少覆盖两台 Mac、一个服务器来源、两个 macOS 客户端和两个浏览器入口。比较稳定键集合、显示字段版本和实际来源；新增/撤下一个来源 Agent 后，各客户端一致更新。重复刷新不产生副本，来源休眠不丢目录，执行失败不伪装成设备离线。真实账号、跨机器任务和合成协议测试分别留证。
