# Nango 与群聊 MCP 设计

关联：GET-538。用户已授权研究、设计后直接实现。实现仓库为 getyak/agentroom；保留 AgentStudio 兼容标识与资料路径。

## 意图与范围

把已连接的 MCP 工具变成各个本机 Agent 可以主动发现、提出调用的能力。一个连接可以供多个 Agent、多个聊天复用，但是否可发现与是否批准一次操作是两项决定。群聊中的工具结果按接受时的成员范围发布，凭据始终由 utility 持有。

本期支持 Codex、Claude Code、Pi。A2A 和 Grok/Muse/Dots/Cue 沿用提供方自己的工具，不把本机凭据注入不可控远端。界面说明这一能力边界。已有任务/MCP 联系人与作品协作继续工作。

## 方案选择

1. 每个 CLI 配置真实远端 MCP：改动少，但认证、群范围、审批与撤销散落于 CLI，全局配置还会影响其他项目。
2. 在 AgentRoom 内新造执行器与审批：能集中控制，但重复现有运行与决定台账，增加未知写入重放风险。
3. **采用：复用私有 ToolSessions，增加 MCP 搜索与申请工具；申请产生现有 worker 的精确 MCP 子运行。** 子运行复用原消息、执行联系人和成员快照，先出审批卡，再由现有 executor claim 执行。结果作为该 Agent 的具名消息进入原聊天。模型本轮收到申请回执，不能把申请当执行结果。需要继续推理时，用户可以针对结果继续聊天；本期不增加无限自动唤醒链。

选择由本轮实施者依用户“直接按照方案实现”的授权作出。

## 接入与凭据

- 通用 Streamable HTTP MCP：保留 URL + 可选 Bearer；禁止任意认证头与任意 shell 配置。
- Nango：增加专用入口。用户提供 Nango API 地址、API key、明确的 integration ID / connection ID；服务端用 `POST /sessions` 创建 tenant.connections.pinned 会话，`expires_in: 1h`，禁用 nango_proxy 与动态建连接。工具名白名单可选；留空表示用户明确选中的单一连接的全部工具。
- Nango 管理 API key 只用于创建/结束作用域会话，保存于现有加密 vault，不暴露给模型。运行 token 单独保存在 vault，普通连接响应仅含是否配置、失效时间与非秘密绑定。
- 刷新过期会话是显式用户动作。新会话生成新连接身份，原审批不能移用于新会话；界面显示过期/重新连接入口。避免后台刷新在审批等待期间悄悄改变身份。
- 也允许通过通用入口直接连接 Nango 已有 scoped session MCP URL + token。

## 可用范围

每个 MCP 连接一份版本化访问设置：enabled、contactIds、threadIds、threadContactIds、toolNames；所有列表有上限。默认关闭。联系人与聊天列表同时匹配才可发现工具；threadContactIds 为单个聊天覆盖默认伙伴列表，空覆盖表示该聊天不允许任何 Agent；工具列表空表示该连接全部工具，否则精确匹配。界面可逐项选择，允许在群详情直接管理本群范围。

保存设置前核对联系人为本机可执行 Agent、聊天确实包含对应联系人。所有入口使用固定 IPC 路由。群详情仅修改当前聊天的伙伴覆盖并保留其他聊天与连接默认伙伴。设置不构成外部调用批准，不信任 readOnlyHint。

工具入口只带两个小 schema：`mcp_search` 与 `mcp_request`。搜索按授权连接和工具白名单过滤，再返回有界的工具描述与参数 schema，不注入端点和凭据；申请必须引用实际发现的工具、目录指纹和完整参数。

申请幂等绑定原运行与 tool call ID。一个普通运行最多提出 10 个 MCP 操作；目录指纹、访问设置版本、连接身份、成员身份与接受时受众绑定到子运行。设置、成员或联系人 binding 改变后，worker 在派发前再检查并阻止旧申请。

## 执行与恢复

复用现有 Decisions 精确审批、参数校验、只发一次 claim、尝试记录、未知结果与可选读回。父运行结束不撤销已接受的子请求；关闭访问设置、移除成员或连接会阻止尚未派发请求。已派发操作仍保留回执/unknown，不声称撤销回滚。

目录发现支持分页，设总量与页数上限，检测重复 cursor；不静默漏掉下一页，也不无限拉取。工具描述、schema 与返回数据都视为不可信数据。

Claude 仅启用本轮 AgentRoom MCP proxy，禁用其余 MCP 与内建工具，不改全局配置；缺少必要 CLI 功能时明确记录工具不可用并保留聊天能力。

## 交互

连接页新增 Nango 表单和每个 MCP 连接的“哪些伙伴在哪些聊天可用”折叠设置。默认安静展示连接状态与范围；高级工具白名单按需展开。聊天详情提供当前会话的工具范围入口。审批卡沿用实际发送者的名称，并显示服务、工具与参数；不增加普通聊天发送确认。

## 验收

合成 MCP 服务验证：有权限可发现；其他 Agent/群不可发现；申请无网络写入；批准后恰好执行一次；同 ID 不同参数冲突；目录/凭据/成员/权限变更拒绝旧申请；重启不重放；分页工具可找到。Nango 合成服务核对 pinned tenant、禁用 proxy、session token 不进入响应与 SQLite 明文。CLI 参数测试覆盖三个后端。

运行宿主后端测试、personal/desktop 类型检查、构建与浏览器交互验收。真实 Nango 账号/真实第三方作用须有可用凭据才能单独验收，不能用合成结果代替。复杂权限变更须独立 agent review；修复确认的 P0/P1 后才按仓库门禁交付。
