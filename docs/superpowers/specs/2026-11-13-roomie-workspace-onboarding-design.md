# Roomie：把首次进入变成一个真正可用的本机工作区

> 历史设计。GET-547 已按新 Roo 身份、统一审批和自动成员拼图适配；当前行为以 [迁移台账](../../migrations/agentstudio-merged-features.md)、API 与客户端合同为准。

日期：2026-11-13。关联：[GET-524](https://linear.app/getyak/issue/72549a21-e7ce-4914-899e-6616fb347f80)。

状态：用户已批准直接实现、测试后合并并安装。后续补充要求以聊天为首次入口，提供可点击联系人申请和话题群建议，配置后保留长期管家，并由明确引导开启持续主动发现。实现与验收状态见 PR 和 `docs/personal/roomie.md`。用户已确认 Roomie（小伴）作为长期工作区管家的定位；具体默认选项与分批范围仍是本文建议。较早的本机发现与角色准备合同仍有效；本文明确指出的扩展需要随实现同步更新 API 和客户端合同。

## 用户想要的结果

用户希望第一次打开 AgentRoom，就有一个 AI 主动了解本机已配置的助手和连接，整理工作目录与资料链接，以尽量少的步骤配好联系人和群聊。支持范围应尽可能完整；“配好了”要有真实配置和执行依据。

这位助手叫 **Roomie，中文“小伴”**，对应 AgentRoom 中帮你安顿好工作空间的伙伴。用户已确认配置后保留为联系人，作为长期工作区管家。它继续接受“把这个项目整理好”“检查哪个助手掉线了”等请求；允许用户隐藏入口，之后仍可从设置找回。

成功标准是：进入工作区时，用户已有至少一个通过真实验证的聊天后端；采用的联系人、项目目录与群聊已保存且能继续使用；剩余登录、授权或不支持项有明确入口。姓名、头像和自我介绍不占据必经步骤。用户可以随时先进入，跳过不等于配置成功。

## 方案取舍

1. **逐项设置向导**：容易实现，但用户仍要理解模型、连接和联系人之间的关系，不符合减少步骤的目的。
2. **给 AI 任意终端权限，让它自行配置所有软件**：覆盖面看似大，但难以稳定确认改了什么，缺模型时无法启动，也容易修改用户全局配置。
3. **本机发现与验证负责事实，Roomie 负责理解目标和组织方案**：推荐。没有模型也能完成发现、连接和最小配置；有已验证模型后，再生成适合用户的角色和群聊。执行依赖固定配置工具与可恢复记录。

第 3 项是作者建议，符合用户已选定的长期管家定位。首次入口用卡片和少量自然语言交互，保留确定性的下一步；不让用户在聊天框里猜连接命令。

## 首次体验：两个主要动作，缺什么才补什么

### 1. 帮我配置

首次欢迎页出现时，宿主自动读取固定适配器允许的本机元数据，以及当前 AgentRoom 资料目录中的已有连接。不会启动 MCP 命令、调用模型、请求新的外部服务或扫描整个个人目录。结果卡片逐项更新，不让一项失败挡住其他结果。已保存的工作区不强制重走引导。

首屏小伴说明：“我会用你已有的助手，帮你准备联系人和项目群。”显示已找到的候选和默认选择的助手、模型、提供商，以及将用于整理的资料类别。主按钮“帮我配置”只在这些事实和资料范围可见时进入可点击状态；点击明确授权最小模型测试与随后的方案整理。次要入口为“先进入”。模型的输入范围变更后，需要重新确认变更的范围。

最短路径为打开后查看发现结果 → 点击“帮我配置” → 查看并采用。发现阶段不调用模型。缺少登录、模型或目录权限时才插入补充动作，“两个主要动作”不作为所有机器两次点击必定完成的承诺。

用户可选填一句用途，例如“主要写代码、调研和写作”，或直接采用“通用工作区”。建议目录以候选卡片展示；需要新增目录时用原生选择器，多选一次完成。没有选择目录也可继续，使用 AgentRoom 自有工作区。

### 2. 使用这套配置

测试后展示可编辑的结果预览：

- 将复用的已有联系人和实际后端。
- 将新建的少量角色；默认最多 3 位，不按安装数量批量建人。
- 将新建的群聊；默认只建议 1 个与当前目标有关的群，未选中不创建。
- 每位角色与每个群的项目目录、工具和资料链接。
- 仍待登录、待授权、暂不支持的项目；失败项不被绿色完成状态掩盖。

点击“使用这套配置”，一次采用选中的本地变更。无需逐个联系人、逐个群反复保存。结束后直接打开建议的群或第一位可用联系人，输入框可用；不自动发欢迎消息或唤醒全部成员。

登录、系统目录权限或新的工具授权在对应动作发生时处理。用户取消其中一项，可以保留其余已确认配置并进入工作区。引导的进度和修改保存在当前资料目录中，重开后可以接着做。

## 尽可能全的发现清单与接入矩阵

“发现”“导入”“验证”“聊天”“执行工具”是不同能力。适配器明确声明各自支持什么，前端不通过软件名称推断能力。新版本接入一个适配器时加入同一清单，不再增加一套引导。

| 类别 | 本轮设计的行为 | 交付边界 |
| --- | --- | --- |
| Codex、Claude Code、Pi | 找 CLI、登录状态、模型、思考设置；复用配置；逐个按需测试 | 三者已有聊天适配；Roomie 规划须另通过下述隔离合同。项目工具首批仅给符合隔离合同的 Codex/Pi，不扩展 Claude 工具适配 |
| Gemini CLI、OpenCode | 保留安装发现、设置入口和明确的能力状态 | 当前没有聊天执行适配，补齐适配与测试之前不纳入可用聊天候选 |
| Grok Bot、Muse、Cue、ChatGPT Dots | 发现当前 AgentRoom 资料目录内已有服务；未连接时提供登录入口 | 延续各服务实验性质、会话隔离限制与实际验收状态；外部浏览器登录不等于 AgentRoom 已登录 |
| 已保存的 A2A 连接 | 复用确切联系人和服务地址；需要时重新检查 | 元数据成功不等于远端真实回复；单会话服务不复制成多个独立伙伴 |
| MCP HTTP(S) | 列出现有服务、工具清单、认证状态；选择后赋予相应角色 | 检查连接与使用工具分别授权；工具连接本身不生成聊天身份 |
| Claude Desktop、Cursor、VS Code 等配置中的 MCP | 第二批按明确配置路径读取有界元数据，预览后导入副本 | 首批不承诺支持所有格式；不修改原配置或直接执行其命令 |
| MCP stdio、本机模型、额外模型服务 | 进入扩展矩阵；显示“待支持”及手动接入入口 | 需独立的进程生命周期、凭据和能力验证，不能只因发现配置就启用 |
| 项目与目录 | 读取本应用既有绑定、用户选中的根目录；受限使用显式配置中的项目候选 | 不遍历整个 Home、不扫终端历史、不从其他应用会话数据库挖路径 |
| 网页、仓库、文档链接 | 接受用户粘贴或应用已有资料链接，去重并归到选定项目 | 网页链接不等于已连接账号；不自动登录或下载链接内容 |

发现记录包含稳定来源标识、采样时间、支持能力与配置摘要。只把经过字段白名单提取的元数据交给 renderer 或模型。原始配置、token、cookie、HTTP header、完整环境变量不进入提示词和日志；必要的凭据引用只在宿主保存。

路径、连接名称、模型名、项目文件和网页都视为资料，不能让它们提供新的配置指令。配置文件不可解析、版本未知或超过读取上限时显示原因，继续其他发现。首批不引入任意全盘扫描或局域网端口扫描。

## 工作目录必须能实际使用

项目是一个可复用的本机资源记录：稳定 ID、名称、规范化的绝对目录、显示路径、来源、授权范围与检测时间。允许同一工作区保存多个项目，每位联系人/每个群设置默认项目，每次会话可显式切换。

默认优先级为：本次明确选择 > 会话保存的项目 > 联系人默认项目 > AgentRoom 自有工作区。群聊使用群自己的默认项目，不把成员私聊的目录自动带进群。接受一次运行时固定实际使用的项目与权限；排队后切换默认只影响下一次运行。

保存前由宿主检查真实路径、是否为目录和可读性。目录选择只是引用授权，不意味着修改文件、运行脚本或允许所有群成员读取。基础探测不写入用户项目。需要写入能力时使用单独的实际权限检查与明确授权，不用“只读测试成功”宣称能改代码。

执行仍沿用当前隔离的暂存目录与工具会话。用户项目通过有范围的项目读取工具暴露；不直接把所有后端的进程 cwd 改到用户项目，让它们隐式加载 hooks、技能或未选择的资料。执行适配器未来支持原生 cwd 时，必须另声明能力、处理项目指令和配置副作用，并有专门验收。

首批项目读取仅在具备受限工具会话且通过下述隔离合同的 Codex/Pi 中可用。Claude、A2A 与原生服务可以保存项目引用和资料链接，但界面明确标注暂不能读取本机项目文件；不得因群里有另一位支持读取的成员，就默认把文件转发给这些成员。扩展任一适配器的目录访问须另行验收。

目录穿越、符号链接逃出授权根、嵌套挂载变化、目录被移动或外置盘断开时拒绝相关访问并显示待修复。没有显式改变范围，不自动回退到更宽的父目录。重新绑定保留旧聊天与资源 ID，并递增配置版本。

资料链接按用途标为“参考资料”“代码仓库”或“连接入口”。仅 HTTP(S) 网页可以直接作为网页打开；本地文件通过受控项目资源引用解析，深链交给平台允许列表处理。OAuth 回调单独走原接入流程，不存作公共资料链接。URL 中的凭据和敏感查询参数不得保存到可分享的卡片。

## Roomie 的身份、模型与配置工具

Roomie 是带系统用途标记的一个稳定身份，区别于任何模型品牌；展示“由你选择的 Codex / Claude / Pi 提供”。它不自带隐藏云端模型、不索取所有账号密钥、不偷偷切换提供商。无可用模型时展示诚实的本机配置助手界面，不生成伪造的 AI 回答。

首次选中的已验证后端保存为 Roomie 的配置。用户可之后更换，但执行中的任务保持原快照。仅有远端或原生网页助手时，首批允许直接连接并聊天；不把未验证的结构化配置规划能力标为可用，仍可使用确定性的通用配置模板。

**Roomie 的测试与规划必须由宿主强制隔离。** 不能直接把旧 `AgentOnboarding.execute` 的提示词约束当作隔离证明。每个启用规划的 CLI 适配器须关闭未选中的用户记忆、hooks、skills、项目上下文、已有 MCP 及内置工具；使用自有暂存目录与受控环境，只保留实际选定的认证、提供商传输配置、模型和思考参数。模型不获得配置文件原文或认证秘密。只读沙盒也不代表禁止读取其他文件，必须验证这些额外限制实际生效。

支持的 CLI 版本和能力须由适配器检测并以合成注入案例验证。某个版本或自定义提供商无法在上述隔离下运行，就显示该限制并退回确定性模板，或由用户明确选择另一个可支持的候选；不放宽隔离、不换账号或传输地址。用户原有普通聊天保持现有合同，不因新引导强行迁移。受限项目会话同样使用这一执行合同，只增加本次明确授权的项目工具。实现时可复用现有 guest/tool-session 的经过验证部分，但不能直接复用其内置提供商假设或忽略用户配置的行为来替换用户的实际提供商。

Roomie 的后台动作建议收敛到以下职责，具体 API 名称留给实现：

1. 读取当前发现快照、既有联系人/群概况和已选择的项目元数据。
2. 请求固定适配器做连接或最小执行测试，不拼接模型生成的终端命令。
3. 生成有版本、带来源的配置提案；用户目标与“通用模板”也是合法来源。
4. 应用用户选择的那份提案；新建/复用联系人、创建选中的群、绑定项目和资料。
5. 读取配置操作回执；报告失败与下一步；取消或继续未完成的准备。

普通对话仅允许已有聊天授权覆盖的数据。增加连接、扩大目录访问、启用工具或把联系人加入已有群时，使用对应配置动作及范围预览。以后“帮我加个研究助手”可以在一个提案卡片中处理，不重新走完整欢迎页。

## 冷启动、角色与群聊如何组织

没有历史的用户不应得到“没有来源，无法建议”。把用户输入目标记录为 `owner_goal` 来源；用户未填写时使用明确标为 `starter_template` 的通用建议。模板只说明建议用途，不推断用户的习惯或声称分析了其项目内容。首批可给出通用助手和可选的研究/写作角色；不为凑数创建角色。

完全没有可聊天后端时，可以保存项目、资料链接与 setup/proposal 草稿；不创建无后端联系人、不可用群或伪装成已可聊天的 Roomie 记录。首屏仍以“小伴配置助手”展示确定性界面。接入一个可用后端后才可采用角色和群，并完成 Roomie 联系人绑定。只有已有服务聊天可用而没有隔离规划后端时，用明确标为模板的提案复用已有联系人；不为单服务会话批量复制身份。

有历史时，默认只参考已添加的角色和群概况；群消息、保存的记忆、项目文件内容各自显式选择。新的 Roomie 流程不沿用旧界面默认开启的历史开关。既有准备任务保持原快照，不能更改其资料范围。

角色草稿包含名字、分工、实际后端、模型与思考配置、项目、允许的工具、适合的群。每个字段都可编辑，模型生成的 ID、来源和能力必须经服务端核对。默认尊重已有联系人，不因名字相似而合并；用户明确选择“复用”才引用其 ID。

新群预览展示标题、成员、每位成员的分工、默认项目和可见资料。首次一键采用只可创建选中的新群；加入已有群、修改现有角色或重配已有工具作为单独可见差异，默认不选中。已有群成员策略不变；新群复用当前 `auto` 参与合同，允许静默，不用每条 Agent 回复无限唤醒所有成员。

批量采用是用户确认预览后的专用本地配置动作，不是模型直接调用 `group_create`。复用 Messenger 的联系人/私有群校验，并核对当前群规则与数量上限；关闭 Agent 建群时，该提案中的建群项不可自动采用，保留手动建群入口。Claude 等已有聊天联系人是否能进入普通私有群，依现有 Messenger 合同；不把现有模型建群工具仅限 Codex/Pi 的过滤条件冒充所有群的限制。模型自行操作群仍保持原 group-tools 权限；本轮不新增公开邀请或外部成员，也不改变共享群的成员范围。

人类联系人不会凭空成为好友。可以整理已有联系人，但不能导入本机通讯录后就宣称已建立真实投递关系。邀请真人和跨设备同步继续使用各自的真实接入流程。

## 配置提案、保存与恢复

在当前 personal SQLite 和已有队列中增量保存，不另起一个 Agent 集群。逻辑记录可合并进现有表，不要求每个概念独占一张表。

| 记录 | 必须保存的事实 |
| --- | --- |
| DiscoverySnapshot | 当前资料目录、时间、来源、能力、非秘密配置版本和逐项结果 |
| WorkspaceSetup | 阶段、所选后端和资料范围、目标、探测结果、错误、取消状态、提案 ID |
| ProjectResource | 稳定 ID、真实目录引用、授权根、权限范围与版本；仅宿主持有完整路径 |
| SetupProposal | 输入快照版本、来源、草稿实体引用、新建/复用差异、默认选中项 |
| SetupApplication | clientId、提案版本、选中动作、预期配置版本、实体 ID 映射及每步结果 |

准备状态为 `discovering → needs_input / ready_to_test → testing → proposing → review → applying → ready / partial`。失败、取消和中断单独保存。导航完成、配置准备完成和真正可聊天是不同事实；跳过欢迎页只改变导航状态。没有成功后端时不能写“所有配置完成”。

本地应用先完整验证提案及引用，再在单个 SQLite 事务中写入联系人、群、项目绑定和应用回执，避免半个群或重复联系人。每次接受生成固定的实体 ID 映射；相同 clientId 和同一应用重试返回原回执。验证失败不落部分本地关系。

网络登录、远端测试与第三方写入不包进数据库事务。首批采用动作只保存本地配置；不能让同一个“使用这套配置”隐式开账号、安装软件或发外部消息。远端检查结果不确定时先核对原操作，不自动重发。

应用前检测变化：联系人已删除、连接/账号/模型配置版本改变、目录权限失效，都使受影响动作待复核；保留用户编辑。其他无关联系人改名不让整个提案失效。后台失联或 App 重启后恢复可见进度，不自动切后端或重复跑模型。

采用后提供“查看这次配置”。可撤销尚未使用且没有新引用的本轮新建对象；已经产生聊天或被用户修改的对象保留，并说明只能解除本轮绑定。撤销不抹除聊天、资料、全局 CLI 配置或第三方账号。

## 分批落地

1. **先跑通完整体验**：统一首屏、已有本机/服务发现、确定性无模型路径、真实本机验证、Roomie 身份、项目选择和受限读取、冷启动角色建议、批量采用联系人与新群、恢复与失败回执。复用现有 HTTP MCP/A2A 和原生服务入口，不等所有接入都完成。
2. **扩大可导入范围**：按提供商增加 MCP 配置发现、stdio 生命周期和认证引用；补 Gemini/OpenCode 的独立适配与端到端验收；增加显式本机模型/模型服务连接。
3. **持续整理**：配置后保留 Roomie，支持增量项目整理、失效连接修复与定期手动检查。是否定时扫描另行设计，首批不开后台定时任务。

每批功能有实现 PR 和对应验收；本设计 PR 不把这些能力标成已交付。

## 验收：配完之后确实能用

- 空白资料、没有 CLI：发现仍可运行；连接入口与跳过可用；不出现假 AI 回复。
- 仅安装未登录、配置缺模型、认证失败、额度不足、适配器不支持分别显示；一项失败不挡住其他候选。
- 使用用户实际选择的后端/模型完成随机挑战，保留测试时间与执行快照；不得以安装、登录探针或模型自述代替测试。
- 完全空白与只有工作目标两种情况下都能生成有明确模板/目标来源的建议；没有历史时无习惯推断。
- 真实选目录 → 保存绑定 → 支持项目工具的 Codex/Pi 读取该目录中的合成验收文件 → 会话重新打开仍能使用；目录脱离、越界和外置盘离线有明确失败。不支持项目读取的联系人只显示引用，不误报读取成功。
- 在隔离空间一次采用角色、群、项目与链接；双击、超时重试、重启后重试都不重复创建。事务故障不留下部分本地关系。
- 采用后用实际后端在新私聊和选中新群完成一条合成交流；新群成员与目录范围吻合；不自动把私聊历史或未选文件交给群成员。
- 已有工作区保持联系人 ID、会话、群策略、模型和工具权限；重新引导不覆盖旧设置，单服务会话不复制成伪隔离伙伴。
- 项目内容、恶意配置项、链接、模型生成 ID 和指令注入不能发起任意命令、越界目录访问、修改全局配置或泄露秘密。
- 测试/规划过程注入全局 hooks、记忆、技能和现有 MCP 的合成标记，证明隔离后没有加载或执行；版本/传输不兼容时实际回退模板，保留原提供商与账号。
- App 关闭/重开、离线、中断和部分登录完成后可以恢复；用户取消不会后台继续模型调用或重复外部提交。
- 桌面键盘与窄窗口验收覆盖首屏到首条真实回复；UI 检查依照更新后的 `docs/clients.md` test ID 合同。

单元测试覆盖策略和事务故障；合成连接/浏览器验收覆盖交互；真实 CLI/服务与安装包验收另行记录。CI 通过不等于真实账号、目录权限或安装包验收通过。
