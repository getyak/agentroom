# 联系人、聊天与审批

GET-483 · 2026-11-10。当前默认 Mac 入口是个人 IM，先连接本人和自己的 Agent。界面采用 Telegram 式的窄导航、会话列表、蓝色动作和简洁消息气泡。人类联系人可以添加，但当前没有跨设备网络投递；保存、送达和实际回复分开表述。

## 开始使用

1. 打开“联系人”。系统发现这台 Mac 的 Codex、Claude Code、Pi、Gemini CLI、OpenCode，并把已有的 A2A/MCP 连接列为联系人。Codex/Claude/Pi 当前有可执行的本地 adapter；未安装、待登录和暂未支持执行分别显示。
2. 点“添加联系人”，优先看到这台 Mac 已有的助手。配置完整时点“添加并聊天”，沿用现有身份和模型配置直接进入对话；已添加的助手显示“打开聊天”，继续原对话。检测到登录配置不代表已经验证执行。需要登录或完善模型的助手提供对应设置入口，暂不支持聊天的助手收在次要列表。
3. 需要研究伙伴、写作伙伴等独立身份时，从添加页底部进入“自定义角色”：先选助手，再填写名称和回复方式。头像、用户名、简介与模型选项按需展开；收起不会清除已有设置。“添加人类联系人”也在此处，当前仍仅本机保存。更改身份从之后接受的消息起生效。
4. 点“发送消息”打开私聊。再次打开同一个联系人会继续原聊天，不会每次建立新任务。文本和附件只保存一次，回复带具体身份，成果原文仍可打开和保存。
5. 从新聊天入口建群，或从私聊右上角创建新群，选择成员和名称。群默认把你的消息交给所有可用成员，本机 Agent 按角色和上下文决定回复或保持安静；`@用户名` 和回复表示明确找它。群信息可逐位设置“按角色判断”“仅提及或回复时”“每条消息”或“暂停回应”，已有显式策略保留。
6. `@all` 只调度可执行成员。不可用/有未知结果的成员跳过并说明原因，不阻挡其他伙伴。Agent 的回复不会再触发 Agent，没有自动互相唤醒循环。显式要求不可用成员回复会保留草稿并给出准确错误。
7. 向已连接的聊天 Agent 发消息即可直接得到回复，Muse 等远端联系人与 Codex 使用同一套聊天流程，无需逐条审批。MCP 工具调用和原有任务转发仍展示具体目标、身份、内容/参数，在“审批”集中决定。批准只授权该版本动作，不等于送达、执行成功或外部效果已经核验。服务自身要求的操作确认也不会自动批准。

## 响应与上下文

| 场景 | 行为 |
| --- | --- |
| 私聊 | 当前联系人直接响应，不自动切换到其他服务 |
| 群内普通消息 | 默认交给可用成员；本机 Agent 可选择沉默，沉默不生成气泡或成果 |
| `@handle` 或回复 | 为群内目标提供明确注意力；仅提及策略只唤起目标，按角色策略仍接收消息自行判断 |
| `@all` / 每条消息策略 | 各成员形成独立的顺序执行；不可用广播成员明确跳过 |
| 一位成员等审批/结果未知 | 保留它的动作与核查状态，其他成员可继续 |
| 新要求发给另一位成员 | 不撤销原成员的审批 |
| 更新身份/群成员 | 已接受的执行保留原身份、成员、后端和上下文快照 |
| 新成员加入 | 不传入群前消息；入群前接受的运行即使后来回复，也保留原接收成员范围 |
| 后台中断或回执丢失 | 保留原操作标识，未知副作用先核查，不盲目重复执行 |

运行快照只给当前 Agent 自身的身份指令；群内其他人只有名称/用户名/简介等身份卡。群与私聊相互隔离，原 CLI 的插件权限边界没有因此变成强制文件系统隔离。A2A 联系人消息直接发送这个可见范围的上下文；MCP 计划和调用使用相同可见范围。接受消息时私下固定连接目标和凭据绑定，排队或重试时发现更换会阻止发送。旧的待审批记录仍需明确处理。

联系人使用相同的消息与回复模型，接入方式由各自 adapter 负责。人类联系人目前仅在本机保存；跨设备加好友及同意请求尚未实现。宿主状态可以作为未来推荐 Agent 配置的依据，但推荐需由用户接受，不会自动安装、连接、改模型或分享历史。

草稿按聊天分别保存。异步回包不能清掉后来写的文字；网络超时保留原请求及 clientId，明确未接受的 4xx 拒绝则允许修改重发。存储写满后保留窗口内的每段草稿，提示重载无法保证恢复。历史任务直接在同一聊天界面继续，不再切换工作台。旧草稿、附件、执行方式和连接自动恢复；未确认请求保留原 clientId、原记忆快照和精确正文，等待手动重试。新聊天里的“整理资料”可继续尚未建立会话的旧草稿。原 `?workspace=tasks&thread=…` 链接仍能打开对应会话。已保存的新草稿优先，旧存储作为恢复备份保留。创建回执迟到时，不覆盖目标会话新写的内容。

点击聊天右上角信息或成果按钮，可以查看全部成果版本、执行与审批记录；详细回执按需展开。联系人/群成员设置在聊天标题中打开。连接、记忆、阅读和审批共用同一套字体、蓝色操作与明暗主题；后台失联后可显式恢复自有后台。

## 参考研究与取舍

Raft 的公开 HEAD 在本轮读回为 [`db5e399f017d584e49597e3a28757645d6807893`](https://github.com/botiverse/raft-source/tree/db5e399f017d584e49597e3a28757645d6807893)。本轮重新读取固定版本 DM、profile、mention 手册及 `peerCard.ts`，并沿用[此前针对同一快照的源码观察](research/raft-observation.md)。未启动 Raft，也未将其源码或私人会话复制进产品；下面是行为分析与独立设计。

| 产品 / 一手来源 | 观察 | 在 AgentRoom 的取舍 |
| --- | --- | --- |
| [Raft DM](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/manual/agent-knowledge/dm.md) | 私聊按参与者复用，身份卡帮助恢复交谈对象；手册还注明已有 DM 加人 UI 的限制 | 按稳定联系人 ID 复用私聊；显式建群/加人，新群不默默复制私聊历史 |
| [Raft peerCard.ts](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/cli/src/ax/peerCard.ts#L53) | 按当前上下文记录是否实际展示对方身份，输出失败不把卡片记作已看见；机制受配置开关影响 | 每次接受消息直接快照身份，不依赖模型记住某个 UI 卡片；当前版本无跨运行时的 seen-card 协议 |
| [Raft Agent Profile](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/manual/agent-knowledge/agent-profile.md) | 身份与运行状态分开；不同类型 Agent 对身份修改有权限差异 | 联系人身份可独立编辑；执行能力/登录状态单列，身份名称不冒充服务账号认证 |
| [Raft mention](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/manual/agent-knowledge/mention.md#L292) | 成员可见性、被动投递与显式注意力不同；提及是聚焦回应的信号 | 群成员范围由服务端核对，响应策略确定化，不要求模型自己遵守“少插话”；禁止回复自动形成机器人循环 |
| [Telegram Bot Features](https://core.telegram.org/bots/features) | 机器人是有身份的聊天对象；群内隐私与可交互消息有明确能力边界 | 用消息型 UI 和独立身份；审批是可追溯动作，采用极简导航与蓝色强调。视觉是本项目的设计判断，不声称 Telegram 授权或协议兼容 |
| [Signal Group chats](https://support.signal.org/hc/en-us/articles/360007319331-Group-chats) | 选择联系人、命名、创建的短路径；成员与权限有独立设置 | 简洁建群和按需展开的成员/策略设置，不要求先建组织、频道或项目 |
| [Slackbot](https://slack.com/help/articles/202026038-How-to-work-with-Slackbot) | 信息访问跟随可见范围，共享写入有明确确认 | 复用执行进度和精确审批；视觉和主要导航不采用频道工作台 |

Raft 是 FSL-1.1-ALv2 source-available 镜像，本项目独立实现上述机制，没有移植它的实现。不会把身份卡、通知投递或 Agent 自述当作真实执行证明。

## 开发与验收入口

数据仍是现有个人 profile 的 SQLite WAL，新增联系人记录与聊天字段；旧记录无需破坏式迁移。桌面仍由独立 preload 的固定 IPC 访问自有 utility，生产 renderer 不发 API HTTP。十一个后端模块均参与复制、watch 和运行指纹。协议见 [API](../api.md#personal-contacts-and-messaging)，界面 test-id 见 [客户端合同](../clients.md)。

```sh
pnpm --filter @agentstudio/personal build
node --test apps/personal/server/messenger.test.mjs
node dev/messenger-acceptance.mjs
node dev/conversation-acceptance.mjs
pnpm --filter @agentstudio/desktop build
node dev/messenger-acceptance.mjs --native
node dev/conversation-acceptance.mjs --native
# 明确使用现有 Codex 配置，只有合成输入，无私人资料：
node dev/messenger-real.mjs --real
```

`AGENTSTUDIO_MESSENGER_EVIDENCE_DIR` 选择产物父目录；每轮使用独立目录和 profile。合成验收不调用真实模型；`--real` 另行记录实际 CLI 状态，不能用登录配置代替真实执行。实际安装包可用 `AGENTSTUDIO_PACKAGED_APP` 指定后运行同一流程。远端私人账号、真实 Claude 执行、跨设备多人、推送和公网服务不由这些测试证明。

## 连续提问与联系人配置（GET-485）

生成中可以继续输入、发送，追问显示自己的排队位置；每个回答始终放在对应问题下面，完成后替换同一位置的临时正文。回复状态分为准备、思考、正文生成、保存和失败；不显示模型内部思考内容。聊天和执行记录不提供停止按钮。要请助手停下或改变方向，直接发送 `stop`、`先停一下` 等普通消息，由对应 Agent 理解和处理，应用不会按关键词强制取消或提前标记已停止。当前同一 Agent 的消息按顺序执行，忙碌时后续消息会排队，不能保证立即打断正在运行的 CLI。失败或中断后保留已收到的正文，并标明未完成，不冒充成果。滚动查看旧内容时不强制拉回底部。

创建或编辑联系人会显示保存的默认模型、提供商和思考深度，可继续跟随本机，或固定该联系人的模型与深度。Pi 可用模型来自无 prompt 的 RPC 元数据，思考选项按该模型实际支持档位过滤。保存的默认值变化自动触发更新，也可点重新读取；终端临时切换并不修改启动默认。已接受的消息与重试保留原模型，只有新消息跟随变更。不可确认或不可用的模型明确阻止发送，不自动改用其他提供商。

Pi 的“提取身份”仅在点击时读取其全局 `SYSTEM.md`、`APPEND_SYSTEM.md`，填入最多 3000 字供检查，超长明确提示；需保存联系人后才使用，不导入工作区 AGENTS 或凭据。头像可选择角色图标与颜色，默认助手也有可辨识的标志。正文采用 15px 系统字体、舒展行距和中性气泡，代码和表格独立承载并支持窄窗横向滚动。设计研究见 [本机 Grok 观察](research/grok-conversation-observation.md)。

## 让助手建议角色

在联系人底部或发起聊天菜单打开“让助手建议角色”。选择本机助手，按需补充目标；“参考当前工作区”可以关闭近期群聊文字或已保存的记忆。先用选定的实际模型完成最小运行测试，通过后才生成建议。每条建议说明理由、来源、身份指令和可能适合的现有群聊；从资料推测的习惯单独注明，不冒充你明确设置的偏好。

采用后创建一个绑定本次测试模型的联系人，不自动加入旧群或改写已有身份。刷新、关闭后回来可以恢复结果；执行失败、额度不足和中断会保留准确状态，不切换提供商、不自动重试。准备期间可以取消。每次准备通常调用模型两次，群聊自动参与也会逐成员调用模型；外部 Agent 仍须按具体请求审批。Agent 回复不递归唤起其他成员，其他成员会在后续可见上下文中看到它。

准备只使用当前个人数据目录的有界角色/群概况，以及可选的近期群聊用户文字和显式记忆；不读取私聊、其他项目或终端历史。新 Agent 的群聊历史可见边界依旧从入群后开始。

## 每位 Agent 的目标与调度

点击私聊顶部的联系人，打开「Agent 设置」：身份与基本设置、当前目标、运行安排和最近运行都在这里。群聊顶部打开群信息，成员旁的设置按钮进入同一个联系人配置，返回后仍停留在原群聊。聊天标题只显示对方或群名称与状态；模型放在配置和执行记录中。

目标可先保存，再点「立即运行」；定时默认关闭。支持固定间隔、每天指定时间和本机 Agent 自主续跑。自主续跑由 Agent 决定继续、等待、完成或需要你补充，等待限定在15分钟至24小时，每日上限仍由你设置。所有 Agent 共用原执行队列，手动消息优先，不为每个身份启动常驻进程。只有应用运行且 Mac 唤醒时执行；错过的时段只合并补一次。失败或结果未知会停下，恢复前不重复提交。

联系人页底部的「发现本机助手」只检查自己 Mac 已安装或已连接的伙伴，打开原聊天；「准备合适的伙伴」沿用现有角色建议流程，预览采用后才创建联系人。工具连接本身不推荐成聊天身份；已有 MCP 联系人需要先明确选择聊天助手，原有工具调用仍逐项确认。

第一版每位 Agent 只管理自己的目标和下一次运行。跨 Agent 派工和操作系统后台唤醒留待后续。
