# 阿屋 Roo：项目与组队配置

阿屋使用 AgentRoom 应用吉祥物作为固定头像，聊天头部、会话列表、联系人和入口沿用同一品牌图片；连接不同模型时保持这个身份。

首次使用仍从阿屋的普通向导会话开始；侧栏“阿屋 Roo”或引导卡“整理项目与组队”打开扩展配置。内部 `roomie` API 和历史记录保持兼容，不再创建第二位默认助手。它检查支持的本机助手配置，显示可添加的助手；你可以直接填写工作目标，或点一个用途选项。没有模型时仍可保存目标、目录与链接，通过“管理连接”接入自己的账号。

点击本机助手的“添加并完成配置”会使用明确的后端、模型和思考设置进行随机挑战测试。只有测试通过才添加并绑定。阿屋接着给出少量联系人申请和一个话题群建议；逐个添加可以独立聊天，点“创建群聊并配好成员”会在一次本地事务中准备角色与私有群。重复点击不会重复创建。现有聊天和联系人不被改写。

主输入框是持续的配置对话。你可以补充目标、要求推荐新伙伴，或明确要求开一个讨论群；阿屋先测试当前所选后端，再生成建议。所有建群建议都等你点击卡片采用后才创建；旧的自动建群设置不再静默生效。普通聊天中的模型建群、加人和跨聊发送继续走统一审批。不会自动更换阿屋已经选定的聊天后端。

“工作目录、链接与主动推荐”中可选择真实目录、添加资料链接。目录只读，支持受限工具的 Codex/Pi 可以用 `project_list` / `project_read` 读取指定目录中的普通文本；单文件上限 100KB，列表上限100条，不读取隐藏文件、凭据、数据库、密钥或符号链接。目录被移动、替换或越界会拒绝访问。新角色和群保存项目与链接引用；更换默认目录只影响之后添加的对象，已有伙伴与群需要点击列明对象的应用选项。目录读取授权固定原成员、后端和认证/传输身份，新增成员不会自动扩大范围；接受中的执行固定原项目和接收成员范围。原生服务、Claude 等仍可普通聊天，首批不据此赋予本机项目读取能力。

主动发现需要用户开启。开启后每60秒检查已支持的本机配置元数据，也会响应现有配置变更通知；有安装、登录或模型配置变化时更新推荐。它不扫描整个个人目录，不启动未接入的 MCP 命令，也不自动调用模型。忽略的卡片保留忽略状态，可随时关闭主动发现。

配置测试与角色规划首批支持符合隔离合同的 Codex/Pi。Codex 复用现有、通过版本门禁的隔离认证与原生工具路径；自定义提供商/凭据存储不兼容时明确报错，不切换账号或提供商。Pi 禁用全局扩展、技能、上下文文件和内置工具。Claude、Gemini、OpenCode、A2A、原生服务和 HTTP MCP 继续从现有连接界面管理，发现/聊天/项目工具能力分别展示。

准备任务、测试时间、所选配置、建议和采用引用保存在当前 personal SQLite；离开页面不丢进度。应用重启中断的准备不会自动重跑；停止未确认时保留阻塞记录。角色规划失败但已通过连接测试时，可以明确标为通用模板；停止不确定不能伪装为模板成功。

验收入口：`ROOMIE_EVIDENCE_DIR=<受控产物目录> node dev/roomie-acceptance.mjs`；`--real` 使用当前真实CLI与合成目标，`--native` 通过隐藏 Electron 验收。原生验收须先构建，并遵循 [原生测试合同](testing.md)。
